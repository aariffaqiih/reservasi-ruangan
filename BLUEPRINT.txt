

1. **`User` = abstract class**
   Benar, karena menjadi induk bersama untuk `Mahasiswa`, `Admin`, dan `Satpam`.

2. **`Notifiable` = interface**
   Benar, karena hanya mendefinisikan kemampuan menerima notifikasi.

3. **Override yang wajib**
   Yang paling masuk akal adalah `receiveNotification(notification)` pada:

   * `Mahasiswa`
   * `Admin`
   * `Satpam`

4. **`Notification` harus punya penerima**
   Tanpa atribut penerima, relasi notifikasi belum lengkap. Jadi perlu ada:

   * `penerima: Notifiable`

5. **`Reservation`, `Approval`, `AccessRecord` perlu menyimpan relasi objek**
   Supaya diagramnya utuh, masing-masing sebaiknya menyimpan referensi ke objek terkait.

6. **Komposisi tidak wajib dipakai di model inti ini**
   Untuk kasus Anda, **asosiasi** dan **agregasi** sudah lebih tepat daripada komposisi, karena data riwayat biasanya tetap disimpan walau status berubah.

# Spesifikasi kelas per kelas

## 1) `User` *(abstract class)*

**Jenis:** abstract class
**Atribut:**

* `- id: Long`
* `- nama: String`
* `- email: String`
* `- noHp: String`
* `- passwordHash: String`

**Relasi:**

* **is a** → parent dari `Mahasiswa`, `Admin`, `Satpam`
* **UML:** generalization / inheritance

**Override:**

* tidak ada di `User`
* bisa menjadi dasar override pada subclass

**Method:**

* `+ login(email: String, password: String): boolean`
* `+ logout(): void`
* `+ ubahProfil(nama: String, email: String, noHp: String): void`

# Relasi antar kelas yang lengkap

## Inheritance / is a

* `Mahasiswa` **is a** `User`
* `Admin` **is a** `User`
* `Satpam` **is a** `User`

## Interface implementation

* `Mahasiswa` **is a** `Notifiable`
* `Admin` **is a** `Notifiable`
* `Satpam` **is a** `Notifiable`

## Association / has a

* `Mahasiswa` **has a** `Reservation`
* `Reservation` **has a** `Mahasiswa`
* `Reservation` **has a** `Room`
* `Reservation` **has a** `Approval`
* `Reservation` **has a** `AccessRecord`
* `Reservation` **has a** `Notification`
* `Approval` **has a** `Admin`
* `Approval` **has a** `Reservation`
* `AccessRecord` **has a** `Satpam`
* `AccessRecord` **has a** `Reservation`
* `Notification` **has a** `Notifiable`
* `Room` **has a** `Reservation` secara relasi bisnis

## Uses

* `Mahasiswa` **uses** `ReservationService`
* `Mahasiswa` **uses** `NotificationService`
* `Admin` **uses** `ApprovalService`
* `Admin` **uses** `NotificationService`
* `Satpam` **uses** `AccessControlService`
* `Satpam` **uses** `NotificationService`
* `ReservationService` **uses** `NotificationService`
* `ApprovalService` **uses** `NotificationService`
* `AccessControlService` **uses** `NotificationService`
* `NotificationService` **uses** `Notifiable`

## Agregasi yang cocok

* `ReservationService` ◇ `Reservation`
* `ReservationService` ◇ `Room`
* `ApprovalService` ◇ `Approval`
* `AccessControlService` ◇ `AccessRecord`
* `NotificationService` ◇ `Notification`

## Komposisi

* **Tidak wajib dipakai** pada model inti ini
  Jika dipaksakan, justru berisiko salah secara lifecycle data.
